1. Dockerfile 基础镜像问题

现象

Dockerfile 中使用 FROM mcr.microsoft.com/playwright/python:v1.59.0-noble，内网无法拉取。

原因

内网环境无法访问外部 Docker Registry。需要将镜像离线导入。

解决

在外网机器拉取镜像，导出为 tar 文件，传入内网后 docker load 导入。

# 外网
docker pull mcr.microsoft.com/playwright/python:v1.59.0-noble
docker save mcr.microsoft.com/playwright/python:v1.59.0-noble -o pw-python.tar

# 内网
docker load -i pw-python.tar

2. npm/pip 离线依赖问题

现象

内网 PyPI 镜像没有 uv 包，uv sync 无法执行。

解决

去掉 uv，改用 pip install . 直接从 pyproject.toml 安装依赖。通过 ARG PYPI_MIRROR 传入内网镜像地址。

ARG PYPI_MIRROR=https://mirror.gree.com/pypi/simple/
COPY backend/pyproject.toml ./
COPY backend/app/ ./app/
RUN pip install --no-cache-dir --progress-bar off -i ${PYPI_MIRROR} hatchling && \
    pip install --no-cache-dir --progress-bar off -i ${PYPI_MIRROR} --no-build-isolation .
CMD ["python", "-m", "uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]

npm 包在构建前端时（npm run build）已打包到 .next/standalone，Dockerfile 只需 COPY 产物，不需要联网。

3. nginx 基础镜像不是 Alpine

现象 
/bin/sh: 1: apk: not found

内部 nginx 镜像 172.73.0.156:85/public/nginx:latest 是 Debian 系统，没有 apk 命令。

解决

在外网拉取 nginx:alpine，安装好 nodejs 和 supervisor，commit 为新镜像，导出传入内网。

# 外网：制作预装依赖的镜像
docker run -d --name nginx-pw nginx:alpine sh -c "apk add --no-cache nodejs supervisor && sleep infinity"
docker commit nginx-pw nginx:alpine-pw
docker save nginx:alpine-pw -o nginx-alpine-pw.tar
docker rm -f nginx-pw

# 内网导入
docker load -i nginx-alpine-pw.tar

Dockerfile 改为 FROM nginx:alpine-pw，去掉 RUN apk add。

4. Alpine apk 包仓库不可达

现象 
WARNING: fetching https://dl-cdn.alpinelinux.org/...: DNS: transient error
ERROR: unable to select packages: nodejs (no such package)

即使使用 Alpine 镜像，构建时也访问不了 Alpine 包仓库。

解决

同问题 3，使用预装好依赖的镜像，构建时不需要 apk add。

5. Docker BuildKit 兼容性问题

现象 
listing workers for Build: failed to list workers:
Unavailable: connection error: desc = "transport: Error while dialing unable to upgrade to h2c, received 404"
解决

禁用 BuildKit，使用旧版构建器：

DOCKER_BUILDKIT=0 docker-compose up -d --build

或在 docker-compose.yml 的 build 配置中加 network: host。

6. pip 安装线程创建失败

现象 
RuntimeError: can't start new thread

pip 安装包时，进度条渲染需要创建线程，被 seccomp 策略阻止。

解决

加 --progress-bar off 禁用进度条，避免创建线程：

RUN pip install --no-cache-dir --progress-bar off -i ${PYPI_MIRROR} hatchling && \
    pip install --no-cache-dir --progress-bar off -i ${PYPI_MIRROR} --no-build-isolation .

7. 后端启动卡住无日志

现象 
INFO:     Started server process [1]
INFO:     Waiting for application startup.
# 反复重启，无更多日志
原因

uvicorn 的 lifespan 函数（init_db()、load_*_to_cache()）在连接 MySQL/Redis 时因 can't start new thread 挂住，uvicorn 超时后重启进程。

解决

在 main.py 的 lifespan 中添加分步日志，定位卡在哪一步：

@asynccontextmanager
async def lifespan(app: FastAPI):
    logger.info("Initializing database...")
    await init_db()
    logger.info("Database ready.")
    logger.info("Loading cache...")
    # ... 每步都加 logger.info

最终确认是 seccomp 限制导致线程创建失败（见问题 10）。

8. Next.js 绑定地址导致 nginx 502

现象 
connect() failed (111: Connection refused) while connecting to upstream,
upstream: "http://127.0.0.1:3000/"

nginx 连不上 Next.js 的 3000 端口。

原因

Next.js standalone 模式默认绑定到容器主机名（如 f257b7876467:3000），而不是 0.0.0.0:3000，nginx 连 127.0.0.1:3000 被拒绝。

解决

在 supervisord.conf 中为 nextjs 程序设置环境变量：

[program:nextjs]
command=node server.js
environment=HOSTNAME="0.0.0.0"
directory=/app

9. 前端请求后端地址为 localhost

现象

内网页面能打开，但 API 请求发往 http://localhost:8000，跨域失败。

原因

前端代码中 NEXT_PUBLIC_API_URL 默认值为 http://localhost:8000，构建时写入了 JS bundle。

解决

将所有 API 请求改为相对路径，通过 nginx 代理到后端：

// 改前
const getBaseUrl = () => process.env.NEXT_PUBLIC_API_URL || "http://localhost:8000";

// 改后
const getBaseUrl = () => process.env.NEXT_PUBLIC_API_URL || "";

涉及文件：

  • frontend/lib/api.ts
  • frontend/lib/auth-context.tsx
  • frontend/app/login/page.tsx
  • frontend/app/main/guide/page.tsx
  • frontend/app/main/admin/monitor/page.tsx（WebSocket 用 window.location.origin）

10. 容器内无法创建线程（seccomp）

现象 
RuntimeError: can't start new thread

容器内任何 Python 代码都无法创建线程，包括简单的 threading.Thread。即使用 --pids-limit -1 也不行。

根因

Docker 的默认 seccomp 安全配置禁止了 clone 系统调用（Linux 创建线程用的 syscall）。这是宿主机 Docker 守护进程级别的限制，与镜像无关。

验证方法：

# 失败
docker run --rm python:3.13-slim python -c "import threading; threading.Thread(target=lambda:None).start()"

# 成功
docker run --rm --security-opt seccomp=unconfined python:3.13-slim python -c "import threading; threading.Thread(target=lambda:None).start()"
解决

在 docker-compose.yml 中为后端服务禁用 seccomp：

services:
  backend:
    security_opt:
      - seccomp:unconfined

注意：此选项会降低容器的安全隔离性。内网环境可接受，公网部署建议自定义 seccomp profile 而非完全禁用。
